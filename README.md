# Backlog.html

HTML ファイル 1 つで動作するタスクリスト (看板 / テーブル) アプリです。
サーバー不要。タスク・メンバー・レーン・タグなどのデータは HTML ファイル自身に埋め込まれ、
「保存」「ダウンロード」でデータ入りの最新版 HTML が生成されます。SharePoint への配置を想定しています。

## 機能

- **看板 View** … レーンごとの列にカードを表示。ドラッグ＆ドロップでレーン移動・並べ替え
- **クイック追加** … 看板の各レーン下部 / テーブル最下行の入力欄にタイトルを入れて Enter で追加。
  テーブルでは現在の絞り込み (レーン・担当・タグ・マイルストーン・優先度) が新規タスクの初期値になる
- **Table View** … 一覧表示 (1 タスク 1 行のコンパクト表示、タイトルとサマリーは別列)。列ヘッダーでソート、列ごとの絞り込み行、レーン / 担当 / 優先度 / 日付 / カスタム項目はその場で編集
  - **ビュー** … 絞り込み・並び順・列の表示 / 非表示のセットを名前を付けて保存 (ファイルに保存される)
- **タスクの標準項目** … タイトル / サマリー / 概要 / 着手予定日 / 完了予定日 / 着手日 / 完了日、
  レーン / 担当者 / 優先度 (高/中/低) / マイルストーン / タグ。完了予定日超過は赤表示
  - レーン移動で着手日 (先頭レーンから移動時) と完了日 (完了レーンへ移動時) を自動入力 (未入力時のみ)
- **更新履歴** … タスクごとに「いつ・誰が・何を」変更したかを自動記録 (操作者名は 設定 › 基本 で指定)
- **レーン** … 標準は TODO / IN PROGRESS / IN REVIEW / DONE。カスタムで追加・並べ替え・WIP 上限・完了扱い
- **メンバー** … 名前・色・アイコン画像 (64px に縮小して HTML 内に保存。未設定時は頭文字)。一括追加 (1 行 1 名) と複数選択の一括削除
- **タグ** … 設定のほか、タスク編集ダイアログやテーブルの「＋」からその場で新規作成・付与
- **マイルストーン** … 名前・期日 (標準はなし)
- **カスタム項目** … プロジェクトごとに複数追加。型は text / long text / date / list (標準はなし)。
  カードへの表示、テーブルでの列表示・絞り込み・並べ替え、CSV への出力に対応
- **フィルタ** … フリーワード検索、レーン / 担当 / タグ / マイルストーン / 優先度
- **未保存の変更** … ヘッダーの「未保存 (n)」をクリックで変更一覧をモーダル表示。破棄も可能。
  未保存のままリロード / ページ移動しようとすると警告
- **データのみの入出力** … JSON (全データ) / CSV (タスク一覧) のエクスポート、JSON / HTML / CSV のインポート

## データの保存方法

編集内容はブラウザのメモリ上にあり、以下の操作でファイルに反映します。

| 状況 | 操作 | 動作 |
| --- | --- | --- |
| ローカルの HTML を Chrome / Edge で開いている | **上書き保存** (Ctrl+S / ⌘S) | File System Access API で開いているファイルを直接上書き。初回のみファイル選択ダイアログでこのファイルを指定 |
| SharePoint など Web 上に配置している / 他ブラウザ | **⬇ HTML をダウンロード** (Ctrl+S / ⌘S) | 更新を反映した HTML をダウンロード。元のファイルを置き換え (再アップロード) する |

設定 › データ / 保存 からは、次も行えます。

- **ダウンロード時のファイル名** の指定 (例: `project.aspx`)
- **HTML の保存先 (配置場所)** の指定 … SharePoint の URL や共有フォルダのパスをファイル自身に記録。
  ダウンロード後の案内・「未保存の変更」モーダルに表示され、生成 HTML のデータブロック直前にもコメントとして書き出される
- **埋め込み用 HTML (インライン)** のダウンロード … `<html>` / `<body>` を含まない断片
- **ローカルファイルに保存…** … 対応ブラウザで任意のローカルファイルに書き出し
- **JSON / CSV エクスポート**、**JSON / HTML / CSV インポート**

### CSV の入出力

- エクスポートは UTF-8 (BOM 付き) / CRLF で、Excel でそのまま開けます。
- 列: 番号, タイトル, サマリー, 概要, レーン, 担当者, 優先度, マイルストーン, 着手予定日, 完了予定日, 着手日, 完了日, タグ, 作成日時, 更新日時, (カスタム項目…)
- インポートは「番号」が一致するタスクを更新、それ以外を新規追加します。レーン / 担当者 / タグ / マイルストーンは名前で照合し、
  存在しないものは自動作成します。列は見出し名で対応付けるので、順序や一部の列の欠落は問題ありません。

### ベース HTML (アプリ本体) を新しい版に更新する

1. 新しい版の `backlog.html` を開く
2. 設定 › データ / 保存 › インポート で、今まで使っていた HTML ファイル (または JSON エクスポート) を指定する
3. 「⬇ HTML をダウンロード」して、今までのファイルと置き換える

古い形式のデータは読み込み時に自動で新形式へ補完されます。

## SharePoint での利用

- SharePoint Online は `.html` をダウンロード扱いにすることが多いため、ページとして表示したい場合は
  **`.aspx` 拡張子** でドキュメントライブラリに配置してください (ダウンロード時のファイル名を `xxx.aspx` に設定できます)。
- 更新は「⬇ HTML をダウンロード」→ 同名ファイルを再アップロードで反映します。
- スクリプトエディタ Web パーツなどに **インライン埋め込み** する場合は、
  「埋め込み用 HTML (インライン) をダウンロード」した断片をそのまま貼り付けてください。
  CSS はすべて `.backlog-root` 配下にスコープされており、ホストページのスタイルや `<title>` には干渉しません。
  高さは `<div id="backlog-app" ... style="--backlog-height: 80vh">` の値で調整できます。
- テナントでカスタムスクリプトが無効 (NoScript) の場合は動作しません。管理者に確認してください。

## 動作要件

- モダンブラウザ (Chrome / Edge / Firefox / Safari の最新版)。CSS Nesting と `<dialog>` を使用しています。
- ファイルの直接上書きは Chrome / Edge (File System Access API) のみ。他は自動的にダウンロードにフォールバックします。

## ファイル構成

```
backlog.html   アプリ本体 (このファイルだけで動作)
README.md
CLAUDE.md      開発時のルール・仕様の決定事項
```

`backlog.html` 内の構造:

```html
<style id="backlog-style">…</style>                     <!-- スコープ済み CSS -->
<div id="backlog-app" class="backlog-root" data-standalone="1"></div>
<script type="application/json" id="backlog-data">…</script>  <!-- タスクデータ -->
<script id="backlog-script">…</script>                     <!-- アプリ本体 -->
```

保存時はこれらの `<style>` / `<script>` の内容とその時点のデータから HTML を再生成するため、
単体ファイルでもインライン埋め込みでも同じ結果が得られます。

### データ形式 (version 2)

```
title, fileName,
members[]    {id, name, color}
lanes[]      {id, name, color, done, wip}
tags[]       {id, name, color}
milestones[] {id, name, date}
fields[]     {id, name, type: text|longtext|date|list, options[], showOnCard}
views[]      {id, name, filter, colFilter, sort, hiddenCols[]}
tasks[]      {id, no, title, summary, description, laneId, assigneeId, priority, milestoneId,
              plannedStart, plannedEnd, actualStart, actualEnd, tags[], custom{fieldId: value},
              order, createdAt, updatedAt, history[{at, by, changes[]}]}
nextNo
```

## 動作確認

Playwright (Chromium) で `file://` の HTML を開き、タスクの追加 / D&D / テーブル編集 / 設定変更 / ダウンロードを実行して、
ダウンロードした HTML を再度開きデータが復元されること、2 回目の生成結果が 1 回目と一致することを確認しています。
